I reviewed the client-side structure and the uploaded guide. Your architecture is strong: Babylon.js runtime, React/TypeScript UI, `Game.tsx` as orchestrator, EventBus, FSM, damage pipeline, city generation, robot systems, building/prefab systems, and UI overlays. 

## Highest priority improvements

### 1. Break up `Game.tsx`

`Game.tsx` is doing too much right now. It handles:

* system creation
* render loop
* input handling
* multiplayer events
* UI state syncing
* cleanup
* base/garden/lab/shop logic
* vehicle logic
* music logic

Move these into smaller modules:

```ts
GameBootstrap.ts
GameLoop.ts
GameInputRouter.ts
GameSystemRegistry.ts
GameCleanup.ts
GameUIStateSync.ts
```

This will make your game much easier to expand.

---

### 2. Create a `SystemRegistry`

Instead of 30 separate refs in `Game.tsx`, create one registry:

```ts
export class GameSystemRegistry {
  player?: PlayerController;
  weapons?: WeaponsSystem;
  enemies?: EnemySystem;
  effects?: EffectsSystem;
  building?: BuildingSystem;
  prefabs?: PrefabSystem;
  vehicles?: VehicleSystem;

  disposeAll() {
    Object.values(this).forEach((system: any) => {
      if (system?.dispose) system.dispose();
    });
  }
}
```

Then `Game.tsx` becomes cleaner:

```ts
const systemsRef = useRef(new GameSystemRegistry());
```

---

### 3. Stop updating React state every frame

Inside the render loop, this is expensive:

```ts
setStats(...)
setEnemyCount(...)
setJetpackFuel(...)
setPlayerState(...)
setBuildMode(...)
```

React should not update 60 times per second.

Use a throttle:

```ts
let uiTimer = 0;

uiTimer += dt;

if (uiTimer >= 0.1) {
  uiTimer = 0;
  syncGameUIState();
}
```

For low-frequency data like inventory, upgrades, companions, use `0.5s` or event-driven updates.

---

### 4. Improve EventBus typing

Current EventBus uses `any[]`. Upgrade to typed events:

```ts
type GameEventMap = {
  "player:damaged": { amount: number; remaining: number };
  "enemy:killed": { credits: number; experience: number };
  "ui:message": { text: string; duration: number };
};

class TypedEventBus {
  on<K extends keyof GameEventMap>(
    event: K,
    callback: (payload: GameEventMap[K]) => void
  ) {}

  emit<K extends keyof GameEventMap>(
    event: K,
    payload: GameEventMap[K]
  ) {}
}
```

This will prevent bugs across systems.

### 8. Use render classes

Every mesh should have a render role:

```ts
mesh.metadata = {
  renderClass: "enemy"
};
```

Use:

```ts
type RenderClass =
  | "player"
  | "enemy"
  | "static"
  | "projectile"
  | "pickup"
  | "building"
  | "effect";
```

Then graphics rules become easier:

```ts
if (mesh.metadata.renderClass === "static") {
  mesh.freezeWorldMatrix();
}

if (mesh.metadata.renderClass === "enemy") {
  graphics.registerShadowCaster(mesh);
}
```

### 17. Add lifecycle safety

Every system should follow:

```ts
init()
update(dt)
dispose()
```

And every event listener should be removable.

Good pattern:

```ts
private disposers: (() => void)[] = [];

private listen() {
  const onKey = (e: KeyboardEvent) => {};
  window.addEventListener("keydown", onKey);
  this.disposers.push(() => window.removeEventListener("keydown", onKey));
}

dispose() {
  this.disposers.forEach(fn => fn());
}
```
